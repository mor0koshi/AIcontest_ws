## 1. 座標の決め方(チームで統一する)
- **原点 = コースの左下の角**(5m の辺が x、4m の辺が y)。どの角を「左下」にするか、会場で最初に決めて全員で共有する
- 角度は x 軸の正の向きが 0°、反時計回りが正
- `config/map/course.yaml` の `field`(5.0 × 4.0)が実際のコースと合っているか、最初に壁の内側を測って確認する

## 2. 配置を測る(目標: 椅子の中心 ±1cm、角度 ±2°)
シミュレーションでは、椅子の脚とのすき間は 1〜3cm しかない。**椅子の位置の誤差はそのままぶつかる原因になる**ので、椅子は丁寧に測る。

| 対象 | 測るもの | course.yaml |
|---|---|---|
| 椅子(8脚) | 中心の x, y と、向き | `chairs: - {x, y, yaw}` |
| クレーター(2か所) | 中心の x, y | `craters: - [x, y]` |
| スタート | ロボットの中心の x, y と、向き | `start: {x, y, yaw}` |
| コーン(ゴール) | 中心(変わらなければそのまま) | `cone`, `goal` |

椅子の測り方(例):
1. 対角の脚2本(左前と右後など)の中心の x, y を、2つの壁からの距離で測る
2. 椅子の中心 = 2本の中点、向き = 2本を結ぶ線の角度 − 45°
3. 脚の内側の間隔(`chair.inner_x/inner_y`、仮 0.31m)と脚の太さ(`leg_size`、仮 0.02m)は、最初に1回実物を測って直す

## 2b. (試作)椅子を LiDAR で自動で見つける
手で測る代わりに、スタート位置に置いたロボットで椅子を見つけられる(ROS なしの試験では約9割、ROS 上のシミュレーションでは 1〜4/8 を誤差 約2cm で発見、誤検出なし。実機では未確認なので、**今は手で測った値の確かめ用**)。
```bash
# Pi で real.launch.xml を lidar_angle_compensate:=false で起動し、自己位置が落ち着くまで待つ(ロボットは動かさない)
# (LiDAR の角度を丸めないほうが、遠くの細い脚に当たりやすい)
ros2 run aicontest_rover scan_chairs.py --seconds 5 --keep-manual \
    --out ~/AIcontest_ws/src/aicontest_rover/config/map/course_scanned.yaml
ros2 run aicontest_rover make_map.py ~/AIcontest_ws/src/aicontest_rover/config/map/course_scanned.yaml
```
- 見つかった椅子の一覧(位置・向き・見えた脚の本数)が表示されるので、実物と見比べる
- 見つからなかった椅子は、course_scanned.yaml に手で足す(`--keep-manual` を付けると、もとの course.yaml の椅子のうち見つからなかったものが残る)
- このとき地図には椅子がない状態でよい(壁で自己位置を合わせる)
- 書き出した地図とルートで起動し直す: `ros2 launch aicontest_rover real.launch.xml course_path:=$HOME/AIcontest_ws/src/aicontest_rover/config/map/course_scanned.yaml`(スタート位置・椅子の位置をこのファイルから読む)

## 3. 地図とルートを作る・検査する(ノートPC、1分)
```bash
nano ~/AIcontest_ws/src/aicontest_rover/config/map/course.yaml   # 配置を書き換え。auto_route: true 推奨
~/AIcontest_ws/tools/contest_prepare.sh                          # 入力の確認 → 地図とルート → 検査(自動で直す)→ 実機の起動コマンドを表示
```
`contest_prepare.sh` がやること(中身は `make_map.py`):
1. **入力の確認**(`注意(入力): ...` と出る): 椅子が重なっている・コースの外・壁にめり込んでいる・8脚でない・角度がラジアンらしい・
   スタートが障害物に重なっている・クレーターと椅子が重なっている → 書き写しのミスを疑って直す
2. **地図とルートを作る**: 表示される「順番」と、椅子ごとの「通り抜ける向き / 前進・後退」を見て、おかしくないか確認する
3. **ルートの検査と自動修正**: 点どうしが近すぎないか、途中の点が障害物に近すぎないか、点と点の直線が椅子を横切らないか(problem)、
   直線がクレーターを横切り、そのすぐそばに椅子があるか(warning: A* がその間をすり抜けることがある)を調べる。出たら、関係する椅子の
   **通り抜ける向き・回る順番を自動で変えて作り直す**(`自動で変えたところ: ...` と出る)
   - シミュレーション(2026-11-04、最終版のルート18回)では、ルートが原因で脚に触れた3回はすべて problem / warning が出ていて、触れなかった14回はどれも出なかった
   - **それでも `problem:` / `warning:` が残ったら**、その区間を RViz で特に注意して見て、危なければ手で止める。椅子とクレーターが 30cm 以内に並ぶなど、
     どう変えても消えない配置もある。手で向きを決めたいときは、その椅子に `force_pass: <角度>` を足す(例 `- {x: 1.2, y: 1.0, yaw: 30, force_pass: 120}`)
- `warning: ... crater_margin を ... に減らした` と出たら、クレーターの近くを通るルートなので特に注意して見る
- 「どの向きでも入口か出口がぶつかる」と出たら、その椅子の位置の入力ミスを疑う
- 走り方は `drive_mode: forward`(既定): 椅子と椅子の間も、進む向きを向いてから前進する(横滑り対策)。椅子の周り 0.45m 以内は 0.15m/s に落とす
- ルートの点の名前: `_離れる`(出口から軸に沿って離れる)、`_よける`(出口から椅子の横の面に沿って離れる)、`_回る1〜5`(椅子・クレーターの外側の点をつないで回る)、
  `_向き`(進む向きへ回る)、`_手前2`・`_手前`(入口の 0.30m・0.15m 手前の軸の上)、`_停止`(止まって脚を測る)

```bash
~/AIcontest_ws/tools/contest_prepare.sh ~/AIcontest_ws/src/aicontest_rover/config/map/course.yaml --sim
```
- 同じ地図・ルートで、現実に近いシミュレーション(横滑り・計測輪とジャイロの誤差・LiDAR のノイズ)が RViz に出る
- 8脚すべてを通り抜けてゴールまで行くか見る(約3分)。各椅子の入口の手前で止まって脚を測る(1.5秒)のは正常
- 問題なければ、作った地図とルートを Pi に送る(`rsync`)
- **練習用の配置**: `config/map/practice/practice1〜3.yaml`。`contest_prepare.sh <ファイル> --sim` で、配置の入力から確認までを通しで練習できる
  (練習のあとは `ros2 run aicontest_rover make_map.py` で、パッケージの地図とルートを course.yaml のものに戻す)

## 5. 実機
1. ロボットを、`start` に書いた位置と向きに**正確に**置く(置き位置のずれは、そのまま自己位置のずれになる)
2. Pi で起動: `ros2 launch aicontest_rover real.launch.xml lidar_port:=/dev/rplidar`(既定は計測輪2つ + IMU)
   - **ロボット(Nucleo)の電源を入れてから約1秒は動かさない**(BMX055 のジャイロのずれを測る)
   - Pi のログに `[nucleo] IMU found` と出ているか、`/serial_bridge` のログの校正状態がジャイロ 3/3 か確認
   - **スタートで5秒待つあいだにジャイロのずれを測るので、その間は触らない**
3. モニターPCの RViz で、LiDAR の点が地図の壁に重なっているか確認する(ずれていたら RViz の「2D Pose Estimate」で直す)
4. 審判に**自律動作を宣言**する
5. **自律走行を許可して開始**: Pi に USB ゲームパッドをつないでいれば「自律走行を許可」ボタン(`controller.yaml` の button_2)。
   **ゲームパッドがないとき**(プロポは Nucleo につながっていて ROS には届かない)は、モニター PC(同じ ROS_DOMAIN_ID)から:
   `ros2 topic pub --once /controller/allow_auto_drive std_msgs/msg/Bool "{data: true}"`
6. 危ないときは「自律走行を禁止」(button_3、または同じコマンドで `{data: false}`。すぐ止まる)。**プロポの手動スイッチを ON にすると Nucleo が手動操縦に切り替わる**(Pi の指令より優先)。それでも止まらなければ電源を切る

## 6. 1回目と2回目の間(調整時間)
- 椅子の脚にぶつかった・ずれた場所を記録し、原因を考える(椅子の測定ミス / 自己位置のずれ / 速度)
- すぐできる対策: 速度を下げる(`control.yaml` の `max_speed_xy_m_s`)、入口・出口を遠ざける(`pass_distance`)
